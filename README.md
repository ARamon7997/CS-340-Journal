# CS-340-Journal

My approach to software design is that of simplicity, what would make the software function most optimally without making maintenance a slog. What skills that I did develop in terms of skills in the course of the project was being more test happy, and fixing the issues of a specific function, rather than doing the whole thing at once, then play whack a mole with issues and bugs, especially during the final stretch. What I did follow in terms of design process, at least towards the end, was to look at a given function that was needed, complete the code, and test and edit until the function is satisfactory. This is in context of the project, and most of that was done on a copy of the previous weeks code, which was pretty much similar to the final product, just with the needed project functions absent. I would say that if I needed to do it from scratch, I would say start with getting the base html stuff working before focusing on the basic functions, and so on. This has the advantage of ensuring that each function fully works before being fully implemented into the final product, and any issues with full implementation is easily ironed out without nearly half the hunt. Approaching issues, especially some that are so minuscule that finding the character, or lack of one, among the rest of the code, can be time consuming. Aside from looking at the errors and working from there, tinkering around with the logic a little is also helpful, and has worked out in some cases. My approach on the project was vastly different than the assignments, since there was a lot of new additions that needed to be implemented, and as it so happens, the previous assignment was pretty similar to the final work, without the implements requested. In the future, I think having a basic test html with one function at a time, then building up from there, expanding the html as needed would be something that I would like to do, since that would allow for development to clean up the bugs as we go along. Computer scientists deal with computers on a software level, and is overall an important thing to have with hardware because hardware cannot work without the needed software, and visa versa. Our work with Grazioso Salvare can act as a much needed starting point, or foundation, to create a comprehensive, and thoroughly developed website that can potentially help the company rise to prominence. In many case, all that really takes is someone, or a team of people, to get that metaphorical foot in the door, which in the case of our dashboard, can serve as a prototype, an alpha, or an beta build.
